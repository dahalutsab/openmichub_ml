OpenMicHub · setup guide

Install and run it from scratch

Every command, from a machine with nothing installed to a running marketplace with a 300-artist demo catalogue and trained models. Docker does the heavy lifting: no JDK, no Maven, no Python and no local Postgres are needed for the backend.

STEP 01What you need installed

Two things are required. The rest are only for working outside containers.

ToolVersionNeeded for
Docker Engine + Compose v220.10+ / docker composeRequired. Database, API and ML service
GitanyRequired. Cloning the repository
Node.js + npm20 LTS (18.19+ works)The Angular client. It is not containerised
JDK 21 + Mavenexactly 21Optional — only to run the API without Docker
Python 3.123.12Optional — only to run the ML service without Docker
Version trap

The backend needs JDK 21, not a newer one. Lombok does not support JDK 24+, so a current distro JDK will fail the build. Inside Docker this is already pinned and you can ignore it entirely — which is the main reason to use Docker here.

STEP 02Install Docker

Pick your operating system. Each block ends with a verification command — do not move on until it prints a version.

Remove any distro-packaged Docker first

$ for p in docker.io docker-doc docker-compose podman-docker containerd runc; do
    sudo apt-get remove -y $p
  done

Add Docker's own repository

$ sudo apt-get update
$ sudo apt-get install -y ca-certificates curl
$ sudo install -m 0755 -d /etc/apt/keyrings
$ sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
$ sudo chmod a+r /etc/apt/keyrings/docker.asc
$ echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] \
    https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo "$VERSION_CODENAME") stable" \
    | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

On Debian, replace both occurrences of ubuntu with debian.

Install

$ sudo apt-get update
$ sudo apt-get install -y docker-ce docker-ce-cli containerd.io \
    docker-buildx-plugin docker-compose-plugin
$ sudo dnf -y install dnf-plugins-core
$ sudo dnf config-manager --add-repo https://download.docker.com/linux/fedora/docker-ce.repo
$ sudo dnf -y install docker-ce docker-ce-cli containerd.io \
    docker-buildx-plugin docker-compose-plugin

On RHEL/CentOS/Rocky, swap fedora for rhel or centos in the repo URL.

$ sudo pacman -S --needed docker docker-compose docker-buildx

Arch ships Compose v2 as docker-compose, which provides the docker compose subcommand.

Docker Desktop, via Homebrew

$ brew install --cask docker
$ open -a Docker

Or download the .dmg from docker.com. Launch the app once and let it finish starting — the CLI does not work until the whale icon settles. Compose and the daemon group are handled for you, so skip the Linux post-install step below.

Give Docker Desktop at least 6 GB of memory in Settings → Resources; the Maven build stage is the hungry part.

1 — Enable WSL 2 (PowerShell as Administrator)

> wsl --install
> wsl --set-default-version 2

2 — Install Docker Desktop

> winget install --id Docker.DockerDesktop -e

Then open Docker Desktop → Settings → Resources → WSL Integration and enable your distro.

Do this in WSL

Clone and run the project from inside the Linux filesystem (~/projects/... in your WSL home), not from /mnt/c/.... Bind-mounted Windows paths are dramatically slower and break file-watching in the Angular dev server. Every command in this guide then runs in the WSL shell exactly as written.

Linux post-install — start the daemon, drop the sudo

$ sudo systemctl enable --now docker
$ sudo usermod -aG docker $USER
$ newgrp docker   # or log out and back in

Verify before going further

$ docker --version
$ docker compose version
$ docker run --rm hello-world
Expected

A version for each of the first two — Compose must be v2, invoked as docker compose with a space, not the old docker-compose script — and "Hello from Docker!" from the third.

STEP 03Install Git and Node

Git clones the repository. Node runs the Angular client, which is the one piece that is not containerised.

Git

# Ubuntu / Debian
$ sudo apt-get install -y git

Node 20, via nvm

Angular 19 wants Node 20 LTS. nvm keeps it out of the way of whatever your system Node is.

$ curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.1/install.sh | bash

STEP 04Clone the repository

$ git clone https://github.com/dahalutsab/openmichub_ml.git openmichub
$ cd openmichub

With an SSH key on your GitHub account:

$ git clone git@github.com:dahalutsab/openmichub_ml.git openmichub
$ cd openmichub

Every remaining command in this guide runs from that directory.

PathWhat it is
open_mic_hub_service/Spring Boot API, Java 21
open_mic_hub_ui/Angular 19 client
ml_service/FastAPI: embeddings, LightGBM ranker, segmentation
scripts/Key generation, demo export and import
docker-compose.ymlPostgres + API + ML in one command
Note the name

Cloning into a directory called openmichub is not cosmetic. Compose names its volumes after the directory, and scripts/export-demo.sh and import-demo.sh look for volumes prefixed openmichub_. Clone somewhere else and set COMPOSE_PROJECT_NAME=openmichub in .env instead — the next step does that anyway.

STEP 05Configure .env

The stack boots with an empty configuration. Exactly one value matters on a first run.

$ cp .env.example .env

Open it and set these two lines:

.env
ADMIN_PASSWORD=ChangeMe@123
COMPOSE_PROJECT_NAME=openmichub
No default password

Without ADMIN_PASSWORD no admin account is created at all. There is no fallback password — that is deliberate, since SUPER_ADMIN is the only role that can move money. The address defaults to admin@openmichub.com, changeable with ADMIN_EMAIL.

Everything else is optional and inert until set — payments, mail, the chat assistant and social sign-in all stay switched off rather than failing at boot.

VariableDefaultEffect
ADMIN_EMAILadmin@openmichub.comSuper-admin login
ADMIN_PASSWORDemptyEmpty means no admin is seeded
POSTGRES_DBopen_mic_hubDatabase name
DB_USERNAME / DB_PASSWORDpostgres / rootDatabase credentials
API_PORT8181Host port for the API
ML_PORT8000Host port for the ML service
DB_PORT5432Host port for Postgres
CORS_ALLOWED_ORIGINShttp://localhost:4200Browser origins allowed to call the API
KHALTI_SECRET_KEYemptyCheckout returns 502 until set
MAIL_USERNAME / MAIL_PASSWORDemptyGmail SMTP, app password not account password
CHATBOT_API_KEYemptyGitHub Models token for the assistant
GOOGLE_* / FACEBOOK_*emptySocial sign-in buttons stay hidden
Never commit it

.env is gitignored and holds real secrets once you fill it in. If you change the ports here, change them in every localhost:8181 and localhost:8000 command below too.

STEP 06Start the backend

One command builds both images and starts three containers.

$ docker compose up -d --build

That does all of the following, in order, without further input:

  • Starts Postgres 16 with pgvector and waits until it accepts connections.
  • Builds the API image — Maven resolves dependencies inside the container, so your host needs no JDK.
  • Builds the ML image and bakes the BAAI/bge-small-en-v1.5 sentence encoder into it, so the service works with no outbound network later.
  • Generates the RSA token-signing keypair on first run and keeps it on a volume, so restarts do not invalidate issued tokens.
  • Runs the Flyway migrations and seeds the roles and the admin account.
First build is slow

Expect 5–15 minutes and roughly 4 GB of images: the Maven stage downloads the dependency tree and the ML stage downloads the encoder. Every build after that reuses the layers and takes seconds. Watch it with docker compose logs -f.

$ curl localhost:8181/actuator/health
$ curl localhost:8000/health

STEP 08Run the client

The Angular app runs on the host, not in Docker.

$ cd open_mic_hub_ui
$ npm install
$ npm start

Then open http://localhost:4200. The dev server reloads on save.

The backend location is defined once, in open_mic_hub_ui/src/app/environment/environment.ts:

environment.ts
const host = 'http://localhost:8181';

Change that single line to point the client at a different backend — and add the new client origin to CORS_ALLOWED_ORIGINS in .env, or the browser will block the calls.

STEP 09Seed the demo data

A fresh database has roles and an admin and nothing else. The seeder builds a whole platform with a history — artists, bookings, reviews, posts and generated cover art.

$ docker compose exec ml python -m training.seed_world --artists 300 --wipe
Deterministic

The seed is fixed, so this produces the same catalogue on every machine — the same names, the same bookings, the same artwork. That is why sharing the demo usually means sharing this command rather than a database dump.

--wipe replaces everything

--wipe deletes every row the platform owns before seeding. It has to be passed explicitly for exactly that reason. Leave it off on a database whose contents you care about.

FlagDefaultWhat it does
--artists300How many artist accounts to create
--bookers140Organizer accounts that do the booking
--visitors900Signed-out browsers with a browsing history
--seed7Change it for a different but equally reproducible world
--no-artoffSkip generated cover art — much faster, uglier
--wipeoffClear existing platform rows first

A smaller world, if you just want the app populated quickly:

$ docker compose exec ml python -m training.seed_world --artists 60 --no-art --wipe

Check what landed:

$ docker compose exec postgres psql -U postgres -d open_mic_hub \
    -c "select count(*) from artists;"

STEP 10Train the AI/ML

Four separate things, run in this order. Order matters: segmentation reads the embeddings, so the catalogue has to be embedded first.

The whole sequence
$ curl -X POST localhost:8000/embeddings/rebuild
$ docker compose exec ml python -m training.segment
$ curl -X POST localhost:8000/train -H 'content-type: application/json' -d '{"queries":5000}'
$ curl "localhost:8000/signals?refresh=true"
$ docker compose exec ml python -m training.evaluate_recs

What each step does

1 — Embed the catalogue

Runs the pretrained sentence encoder over every artist's own profile text and stores the vectors in Postgres via pgvector. Nothing is trained here; the vectors are the artists'. This powers semantic search and the "similar artists" strip.

$ curl -X POST localhost:8000/embeddings/rebuild

2 — Fit the segmentation

This one is genuinely fitted on the real catalogue: k-means over the profile embeddings, with k chosen by sweeping silhouette and Davies-Bouldin. Re-run it whenever the catalogue changes.

$ docker compose exec ml python -m training.segment
$ docker compose exec ml python -m training.segment --k 9   # force a k, skip the sweep

Or through the API: POST /segments/train. Read the result with GET /segments/report.

3 — Train the search ranker

A LightGBM LambdaRank model over 13 features. Raising queries gives it more synthetic training pairs; 5000 is the sensible default and takes a minute or two.

$ curl -X POST localhost:8000/train -H 'content-type: application/json' -d '{"queries":5000}'

The same thing from the CLI, with the full set of knobs:

$ docker compose exec ml python -m training.train --queries 5000 --rounds 600
FlagDefaultWhat it does
--queries5000Synthetic queries generated for training
--candidatesfrom configArtists scored per query
--rounds600Boosting rounds
--noisefrom configNoise in the simulated preferences
--seedfrom configReproducibility
--out/app/modelsWhere ranker.txt is written

Optionally, re-measure how well the encoder actually separates a genre match from a non-match on this catalogue and feed that back into the generator, so the ranker is fitted against an encoder as noisy as the one it will be served with:

$ docker compose exec ml python -m training.calibrate

4 — Build the platform signals

Co-choice ("often picked alongside"), demand ("in demand this month") and exposure, computed from everyone's history. They rebuild themselves within five minutes anyway; the refresh only saves the wait.

$ curl "localhost:8000/signals?refresh=true"

5 — Measure it

A time-split replay: does it actually recommend what people went on to choose?

$ docker compose exec ml python -m training.evaluate_recs
$ curl localhost:8000/model            # ranker metadata and metrics
$ curl localhost:8000/segments/report  # segment quality

What is actually trained, and on what

Worth being exact about, because "trained" covers three different things here.

ComponentFitted onWhat that means
Profile embeddingsReal catalogueNot trained. A pretrained encoder runs over each artist's own text
Similar artistsReal catalogueNot trained. Nearest neighbours by cosine distance
SegmentationReal catalogueGenuinely fitted: k-means over the real embeddings
Search rankerSyntheticLambdaRank fitted on an explicit generative process in training/generate.py
Be precise about the claim

The ranker is a real model — it learns weights, it is evaluated on a held-out split, and its features come from real artists at query time — but the preferences it learned came from a simulation, because the platform has no record yet of what anyone clicked or booked after searching. Describe it as bootstrapped on synthetic preferences, not as trained on platform data. ml_service/README.md has the measured numbers, the baselines they should be read against, and what closing that gap would take.

Rebuilding after a wipe

After docker compose down -v, this restores the whole demo world from scratch:

$ docker compose up -d --build
$ docker compose exec ml python -m training.seed_world --artists 300 --wipe
$ curl -X POST localhost:8000/embeddings/rebuild
$ docker compose exec ml python -m training.segment
$ curl -X POST localhost:8000/train -H 'content-type: application/json' -d '{"queries":5000}'

STEP 11Sign in

The seeded accounts are throwaway logins for a throwaway database.

Local only

None of the accounts below should ever exist in an environment that faces the internet.

Every seeded account uses the same password:

Admin@123
RoleEmailSees
SUPER_ADMINyour ADMIN_EMAILEverything, including payouts. Password is your ADMIN_PASSWORD
ADMINadmin@demo.openmichub.localAdmin dashboard, users, transactions
ORGANIZERbooker@demo.openmichub.localBooker dashboard, bookings, payment history
ARTISTamber-machine@seed.openmichub.localArtist dashboard, calendar, wallet, posts

An artist's email is their slug — the same string in their public URL — so /artists/amber-machine signs in as amber-machine@seed.openmichub.local. List the rest:

$ docker compose exec postgres psql -U postgres -d open_mic_hub \
    -c "select u.email, a.stage_name, a.rating from users u
        join artists a on a.user_id = u.id order by a.rating desc nulls last limit 20;"
Rate limited

Repeated failed logins start returning 429 after a few tries. Wait a minute rather than retrying in a loop.

STEP 12Optional integrations

All off by default. Each one is a pair of values in .env and a restart.

Social sign-in

Register an OAuth client with each provider you want, using these redirect URIs:

http://localhost:8181/login/oauth2/code/google
http://localhost:8181/login/oauth2/code/facebook
ProviderWhere to register
Googleconsole.cloud.google.com → APIs & Services → Credentials → OAuth client ID → Web application
Facebookdevelopers.facebook.com → My Apps → Create App → Facebook Login → Settings
.env
GOOGLE_CLIENT_ID=...
GOOGLE_CLIENT_SECRET=...
FACEBOOK_CLIENT_ID=...
FACEBOOK_CLIENT_SECRET=...
$ docker compose up -d

That is the whole change. The sign-in page asks the backend which providers are usable (GET /api/v1/auth/providers) and draws a button for each, so a provider you have not configured is never offered.

Both halves or neither

A client id without its secret fails fast at startup rather than offering a button that cannot work. Also: Facebook requires HTTPS for anyone outside your app's own test users, so localhost works for you and not for them.

Payments — Khalti

Leaving the key blank does not disable checkout quietly: every payment attempt fails with 502 and "the Khalti secret key is not configured". Get a sandbox key from dev.khalti.com (Merchant → Settings → Keys).

.env
KHALTI_BASE_URL=https://dev.khalti.com/api/v2
KHALTI_SECRET_KEY=...

Mail and the chat assistant

.env
MAIL_USERNAME=you@gmail.com
MAIL_PASSWORD=your-app-password   # an app password, not the account password
CHATBOT_API_KEY=your-github-models-token

STEP 13Run the tests

Backend — 98 tests

The JDK on a current Linux box is usually newer than Lombok supports, so run the suite in a container:

$ docker compose up -d postgres
$ docker run --rm -v "$PWD/open_mic_hub_service":/app -v "$HOME/.m2":/root/.m2 --network host \
    -w /app maven:3.9-eclipse-temurin-21 mvn test

With JDK 21 actually on your path, cd open_mic_hub_service && ./mvnw test works too. Everything except the context test is a unit test with no external dependency; OpenMicHubServiceApplicationTests boots the whole application and needs a real Postgres — --network host is what lets it reach the one Compose started. Without a database it skips rather than fails.

Frontend — 80 tests

$ cd open_mic_hub_ui
$ CHROME_BIN=$(which chromium) npx ng test --watch=false --browsers=ChromeHeadless

Substitute google-chrome for chromium if that is what you have installed.

ML — 56 tests

$ docker compose exec ml python -m pytest tests -q

pytest is installed in the image on purpose, so the suite runs in the same interpreter and against the same versions the service runs on.

STEP 14Run the API outside Docker

Only worth it if you are editing Java and want a faster loop. Needs JDK 21 on the path.

$ docker compose up -d postgres        # database only
$ ./scripts/generate-keys.sh           # RSA signing keypair
$ cd open_mic_hub_service && ./mvnw spring-boot:run

The keys are gitignored and every environment gets its own pair. Regenerate with ./scripts/generate-keys.sh --force.

Point it at localhost

Outside the Compose network the API cannot reach Postgres or the ML service by service name. DB_URL in .env already uses localhost:5432; set ML_SERVICE_URL=http://localhost:8000 too, or discovery quietly degrades to the plain artist listing.

STEP 15Share a snapshot

Two ways to hand the demo to someone else, depending on whether they can wait two minutes.

Reproduce it from source

The seeder is deterministic, so they need nothing but the repository — and they end up with a byte-for-byte identical catalogue. This is steps 6, 9 and 10 above, and is usually the right answer.

Ship a snapshot

For a demo machine, or when the ranker's weights matter and you do not want them retrained:

$ ./scripts/export-demo.sh demo-export     # about 10 MB
# ... send demo-export/ ...
$ ./scripts/import-demo.sh demo-export     # on the other machine, containers up first

The export carries the database (embeddings and segment assignments included), the generated artwork and the trained model files, plus a MANIFEST.txt saying what is in it.

Deliberately excluded

certs/ — the JWT signing keypair. Sharing a private signing key lets anyone holding it mint tokens for any account on any deployment that trusts it, so the receiving stack generates its own.

.env — your Khalti key and mail password.

Import refuses to overwrite a database that already holds artists unless you pass --force.

STEP 16Everyday commands

$ docker compose ps                  # health of all three
$ docker compose logs -f api         # follow the API
$ docker compose logs -f ml          # follow the ML service
$ docker compose restart api         # pick up an .env change
$ docker compose up -d --build api   # rebuild after a Java change
$ docker compose down                # stop, keep the data
$ docker compose down -v             # stop and wipe data, keys and uploads

A shell inside a container, and a psql session:

$ docker compose exec ml bash
$ docker compose exec postgres psql -U postgres -d open_mic_hub
down -v is not recoverable

It removes the volumes: the database, the uploaded media, the generated artwork, the signing keypair and the trained models. Rebuilding means re-running steps 9 and 10.

STEP 17Troubleshooting

SymptomCause and fix
permission denied … /var/run/docker.sock Your user is not in the docker group yet. Run sudo usermod -aG docker $USER then newgrp docker, or log out and back in.
port is already allocated Something else holds 5432, 8181 or 8000. Find it with ss -ltnp | grep 8181 and either stop it or set API_PORT / ML_PORT / DB_PORT in .env.
No admin account exists ADMIN_PASSWORD was empty at first boot. Set it and docker compose restart api.
Search returns the plain listing, no ranking The ML service is unreachable or has no embeddings. Discovery degrades on purpose rather than failing. Check curl localhost:8000/health and re-run POST /embeddings/rebuild.
ranker: null from /health No model has been trained yet — step 10.3. Model files live on the mlmodels volume and survive restarts.
Browser shows CORS errors The client origin is not in CORS_ALLOWED_ORIGINS. Add it and restart the API.
Backend build fails on Lombok You are building with a JDK newer than 21 outside Docker. Use the containerised build, or install JDK 21.
Flyway refuses to start / checksum mismatch An applied migration was edited. Never edit one — add a new V{n}__description.sql. To start over locally: docker compose down -v.
export-demo.sh: container not found Your Compose project name does not match. Set COMPOSE_PROJECT_NAME=openmichub in .env.
Postgres healthy, API restarting Read the actual error: docker compose logs api | tail -50. Most often a half-configured OAuth pair — a client id with no secret.
Angular dev server never picks up changes (Windows) The repo is on /mnt/c/.... Move it into the WSL filesystem.
Checkout fails with 502 KHALTI_SECRET_KEY is blank. Step 12.

When nothing else works — full reset

$ docker compose down -v
$ docker compose up -d --build
$ docker compose exec ml python -m training.seed_world --artists 300 --wipe
$ curl -X POST localhost:8000/embeddings/rebuild
$ docker compose exec ml python -m training.segment
$ curl -X POST localhost:8000/train -H 'content-type: application/json' -d '{"queries":5000}'
